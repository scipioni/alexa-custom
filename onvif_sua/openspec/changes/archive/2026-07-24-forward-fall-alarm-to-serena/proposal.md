## Why

`ONVIF_SUA` already detects a person falling and publishes a retained `"on"`/`"off"` state to `onvif/<NOME_CAM>/alarms/fall`. Separately, the Serena voice assistant can run a spoken yes/no confirmation that conditionally starts a LiveKit call — but it has no idea a fall happened. We want a fall to make Serena proactively ask *"ho rilevato una persona caduta sul sensore SUA \<sensor name\>, vuoi chiamare aiuto?"* and, on confirmation (or on no answer, as a fail-safe), start the call. The cleanest way to wire this **without modifying Serena's code** is to have `ONVIF_SUA` emit a one-shot command onto Serena's existing MQTT command topic at the exact moment a fall starts.

## What Changes

- `ONVIF_SUA` gains an optional "Serena bridge": when a fall **starts** (the existing `TumbleDetection action=start` handler, already guarded by `alarm_active` so it fires exactly once per event), it publishes one extra **non-retained** message to Serena's command topic `<serena_prefix>/<serena_node>/trigger/run` with a configurable command phrase (per camera, e.g. `caduta camera0`).
- The bridge reuses the already-connected paho MQTT client and the same broker — no new connection, no new dependency.
- Because the emit sits inside the `if not alarm_active:` guard, edge-detection, de-duplication of the 60 s keepalive, and re-arm-on-`off` come for free — no debounce logic is needed anywhere. Reconnect-time state republishing (`worker.py:451`) does not pass through the start handler, so it never emits a spurious trigger.
- New config block `serena:` in `settings.yaml` (+ env defaults in `config.py`): `enabled`, `topic_prefix`, `node_id`, a per-camera command phrase (template, e.g. `caduta {cam_name}`), a startup announcement (`announce_ready`, `announce_template`, e.g. `sensore uomo a terra {cam_name} attivo`), and an opt-in fault announcement (`announce_fault`, `announce_fault_template`, `announce_fault_interval_s`, `announce_fault_grace_s`). Disabled by default.
- **Startup "sensor active" announcement**: when enabled (and `announce_ready`, on by default), the first time each camera is confirmed fully working after startup — stream alive **and** its tumble-detection rule confirmed enabled (`rule_enabled is True`, not merely stream-connected) — `ONVIF_SUA` publishes the rendered announcement to Serena's `tts/set` topic so the user hears "sensore uomo a terra \<name\> attivo" per camera — a truthful spoken confirmation that each fall sensor is actually active. Once per camera per process (no repeat on reconnect or rule flap); reuses Serena's existing `say` path (no Serena code).
- **Fault "sensor NOT active" announcement (opt-in, multi-shot)**: because the absence of the positive announcement is a weak signal for a life-safety system, when `announce_fault` is enabled `ONVIF_SUA` speaks "attenzione, sensore uomo a terra \<name\> non attivo" for any configured camera that is not confirmed working (offline, stream dead, rule disabled/unverified), after a startup grace window (`announce_fault_grace_s`), and **repeats** it every `announce_fault_interval_s` until the camera recovers. On recovery it speaks the active announcement once. Driven by a periodic check over **all configured cameras** (including those never connected), per-camera and independent. Off by default; also reuses Serena's `say` path (no Serena code).
- **Voice-name hygiene**: the camera name is normalized at render time (lowercase, `-`/`_` → space, collapse) before it goes into the fall phrase and the spoken announcements, so it matches and pronounces cleanly. A camera name must **not** contain the word `camera` (case-insensitive): the web rename/save endpoints reject such a name with an alert (mirroring the existing name-conflict alert), pushing operators toward natural room names (`cucina`, `salotto`).
- **No changes to Serena's source.** The response is authored entirely in Serena's `conf/actions/user.yaml` as a `with_wake: false` trigger whose `ask` action drives the yes/no → `livekit_join` + `telegram` flow, including the ask-again-then-call-anyway fail-safe via nested `on_else`. A ready-to-copy example ships in this change's docs.

## Capabilities

### New Capabilities
- `serena-fall-bridge`: On a fall-start transition, forward a one-shot voice-assistant command to Serena's MQTT command topic so Serena runs a spoken confirmation that conditionally starts a LiveKit call. Additionally, announce each configured camera's fall sensor as active via Serena's TTS topic once the camera is confirmed working (stream alive and tumble rule confirmed enabled), and — opt-in — repeatedly announce any camera that is NOT confirmed working (with a recovery notice when it returns). Opt-in, per-camera command phrase, reusing the existing MQTT client and alarm-lifecycle edge trigger.

## Impact

- **Code (ONVIF_SUA only)**: `onvif_sua/mqtt.py` (new `_mqtt_publish_serena_trigger()` / announcement helpers + `_serena_voice_name()` normalizer), `onvif_sua/worker.py` (one call inside the `action=start` guard at ~line 521; per-camera fault driver), `onvif_sua/config.py` (`serena_*` defaults + `settings.yaml` `serena:` parsing + reserved-word warning), `onvif_sua/web/routes.py` (reject a name containing `camera` in `api_rename_camera`/`api_save_camera`) and its shared `_config_add_camera` chokepoint.
- **Config**: `ONVIF_SUA/settings.yaml` / `.env.example` (new `serena:` block); Serena-side `conf/actions/user.yaml` gains one trigger per camera (config only, documented here, no Serena code).
- **Dependencies**: none new (reuses paho-mqtt).
- **External contract**: publishes to Serena's documented command topic `<prefix>/<node_id>/trigger/run` (default prefix `alexa`; `node_id` defaults to Serena's hostname or its `state.yaml` override). Serena's `trigger/run` matches the phrase against `config.triggers` and dispatches it reentrancy-safe on its STT thread. ONVIF_SUA and Serena must share the same MQTT broker.
- **No breaking changes**: the bridge is opt-in (`serena.enabled: false` by default); existing fall-alarm state publishing is untouched.
